# エラーコード定義書

**Task**: T017  
**Status**: Draft  
**Last Updated**: 2026-03-04

---

## 1. 概要

M5StickC Plus2 ファームウェアが生成するすべてのエラーコードの定義と詳細です。各エラーコードには、原因、対応策、再試行可能性フラグが含まれます。

---

## 2. エラーコード一覧

| Code | Hex | 名称 | 層 | 再試行可能 | 説明 |
|------|-----|------|----|---------|----|
| **0** | 0x00 | OK | - | - | 成功応答 |
| **1** | 0xE0 | ER-PARSE | Firmware | ❌ | コマンドの構文解析に失敗 |
| **2** | 0xE1 | ER-PARAM | Firmware | ❌ | コマンドパラメータが無効（範囲外など） |
| **3** | 0xE2 | ER-SIZE | Firmware | ❌ | VRAM 制約超過、または座標が境界外 |
| **4** | 0xE3 | ER-NOTFOUND | Firmware | ❌ | アイテムが見つからない（SET_ITEM） |
| **5** | 0xE4 | ER-TIMEOUT | Firmware | ✅ | 実行タイムアウト（再試行推奨） |
| **6** | 0xE5 | ER-MALFORMED | Firmware | ❌ | フレーム破損（CRC エラー） |
| **7** | 0xE6 | ER-DEVICE | Firmware | ✅ | デバイス HW エラー（LCD 応答不可） |
| **8** | 0xE7 | ER-BUSY | Firmware | ✅ | デバイスビジー（前の描画未完） |

## 3. エラーコード詳細

### ER-PARSE (0xE0)

**原因**:
- コマンドタイプが不正（0x10-0x16 以外）
- フレーヘッダが 0x01 以外
- パラメータ長の宣言値とバイト数が不一致

**引き起こす条件**:
```
0x01 0x99 0x00 <crc>  // 不正コマンド 0x99
0x02 0x11 0x07 ...    // 不正ヘッダ 0x02
0x01 0x11 0x05 ...    // パラメータ長 5 だが 7B 期待
```

**対応策**:
1. MCP ゲートウェイはコマンドの正当性を事前チェック
2. 再試行は**推奨されない**（通常、アプリケーション側のバグ）
3. ログに記録して、ユーザーに「無効なリクエスト」を返却

**再試行**: ❌ 再試行不可

---

### ER-PARAM (0xE1)

**原因**:
- 座標が画面外 (x > 319 or y > 239)
- 半径が無効 (radius > 120)
- テキスト長が超過 (> 128 bytes)
- カラー値のフォーマット不正（RGB565 形式ではない）

**引き起こす条件**:
```
DRAW_CIRCLE: x=400 (> 319), y=120, r=32, color=0xF800
DRAW_RECT: width=0, height=100  // width ≥ 1 必須
DRAW_TEXT: text_len=200 (> 128)
```

**対応策**:
1. MCP ゲートウェイはパラメータ範囲を事前検証
2. 無効な値を「最近傍の有効値」に自動補正（FR-015）
   - x=400 → x=319 に補正
   - radius=150 → radius=120 に補正
3. 補正内容をログに記録

**再試行**: ❌ 再試行不可（補正して再送）

---

### ER-SIZE (0xE2)

**原因**:
- 描画がフレームバッファの VRAM 制約に違反
- 図形がフレーム範囲外に大幅にはみ出す
- 累積描画でメモリリークの可能性

**引き起こす条件**:
```
DRAW_RECT: x=0, y=0, width=320, height=240
           (全画面矩形は許容だが、複数の大規模描画は制約チェック)

背景描画中に複数の円を同時送信 → VRAM 不足
```

**対応策**:
1. MCP ゲートウェイはファームウェアが先行するコマンドの VRAM 使用率を追跡
2. 新しいコマンド送信前に `PING` で余裕確認
3. 必要に応じて `CLEAR_SCREEN` を送信してリセット
4. ユーザーに「画面がいっぱい」を通知

**再試行**: ❌ 再試行不可（CLEAR_SCREEN → 再送）

---

### ER-NOTFOUND (0xE3)

**原因**:
- SET_ITEM で指定した item_id が登録されていない
- アイテムレジストリがまだ初期化されていない（Phase 3 にて）

**引き起こす条件**:
```
SET_ITEM: item_id=7 (登録されていない)
SET_ITEM: 起動直後 (アイテムレジストリ未ロード)
```

**対応策**:
1. MCP ゲートウェイはアイテムレジストリをキャッシュして、事前チェック
2. ユーザーに「アイテムが見つかりません」
3. 既知アイテムのリストを提示

**再試行**: ❌ 再試行不可

---

### ER-TIMEOUT (0xE4)

**原因**:
- 描画実行が 5 秒を超過（大規模描画/複合描画など）
- ファームウェアがハング状態（稀）
- UART 通信が断裂

**引き起こす条件**:
```
DRAW_TEXT: 大量テキスト（> 100 文字）
複数の描画コマンドが積み込まれ、順序待機中にタイムアウト
```

**対応策**:
1. MCP ゲートウェイがタイムアウト後、`PING` でデバイス確認
2. 応答なし → シリアルリセット、リトライ（最大 3 回）
3. 3 回以上失敗 → デバイスオフライン 通知

**再試行**: ✅ 最大 3 回リトライ推奨

---

### ER-MALFORMED (0xE5)

**原因**:
- CRC-16 チェックサムが不一致
- フレーム途中で破損（ノイズ、ボーレートミスマッチ）
- 同期喪失（フレーム開始マーク 0x01 喪失）

**引き起こす条件**:
```
送信中にノイズによる 1 ビットフリップ
→ CRC エラー → ER-MALFORMED

UART ボーレート 9600 で送信、ファームウェア 115200 で受信
→ フレーム全体が破損
```

**対応策**:
1. MCP ゲートウェイは UART 接続確認（ボーレート、パリティ）
2. エラー受信時、フレーム再送（最大 3 回）
3. 連続 CRC エラー（3 回以上）→ UART リセット、リトライ

**再試行**: ✅ 最大 3 回リトライ推奨

---

### ER-DEVICE (0xE6)

**原因**:
- M5Stick LCD ドライバが応答不可（HW エラー）
- TFT メモリエラー（稀）

**引き起こす条件**:
```
LCD 初期化失敗
TFT メモリバス異常 → 描画実行時 fault
```

**対応策**:
1. MCP ゲートウェイが HW エラーを検出
2. ファームウェア再起動（リセットコマンド） → 再初期化
3. 起動後 `PING` でヘルスチェック
4. 繰り返し失敗 → ユーザーに「デバイスを再起動してください」

**再試行**: ✅ デバイス再起動後に再試行

---

### ER-BUSY (0xE7)

**原因**:
- 前の描画コマンドがまだ完了していない
- コマンドキューが満杯

**引き起こす条件**:
```
DRAW_RECT (大規模) を送信
→ 処理中に次の DRAW_CIRCLE を送信 → キュー満杯
```

**対応策**:
1. MCP ゲートウェイはコマンド間に遅延を挿入（応答完全待機）
2. または、キューイング戦略を改善（最新コマンド優先）

**再試行**: ✅ 100-500ms 待機後に再試行

## 4. ステータスコード（成功）

### 0x00 - OK

**説明**: コマンド実行成功

**応答パケット**:
```
[0x01] [0x00] [DATA_LEN] [DATA(optional)] [CRC16]
```

**例**:
```
DRAW_CIRCLE 成功: 0x01 0x00 0x00 <crc>
                  (ステータス: OK, データなし)
```

---

### 0x10 - INFO

**説明**: 情報応答（PING 用）

**応答パケット**:
```
[0x01] [0x10] [0x02] [DEV_ID] [DEV_STATUS] [CRC16]
```

**例**:
```
PING: 0x01 0x10 0x02 0xA5 0x00 <crc>
      (Device ID: 0xA5, Status: OK)
```

## 5. エラーハンドリング決定木

```
Request Received
    ↓
┌─ CRC Check
│  ├─ Failed → ER-MALFORMED (0xE5)
│  └─ OK ↓
│
├─ Header Check (0x01?)
│  ├─ Failed → ER-PARSE (0xE0)
│  └─ OK ↓
│
├─ Command Type Valid? (0x10-0x16?)
│  ├─ No → ER-PARSE (0xE0)
│  └─ Yes ↓
│
├─ Parameter Count Match?
│  ├─ No → ER-MALFORMED (0xE5)
│  └─ Yes ↓
│
├─ Parameter Range Check (座標, サイズ等)
│  ├─ Out of Range → ER-PARAM (0xE1)
│  └─ OK ↓
│
├─ VRAM Available?
│  ├─ No → ER-SIZE (0xE2)
│  └─ Yes ↓
│
├─ Execute Command (with 5s timeout)
│  ├─ Timeout → ER-TIMEOUT (0xE4)
│  ├─ HW Error → ER-DEVICE (0xE6)
│  ├─ Item Not Found → ER-NOTFOUND (0xE3)
│  └─ Success → OK (0x00)
    ↓
Response Sent
```

## 6. ロギング・監視ガイドライン

### 常にログに記録すべきエラー

- ✅ **ER-PARSE**: プロトコル違反（セキュリティ観点）
- ✅ **ER-MALFORMED**: 通信障害指標
- ✅ **ER-TIMEOUT**: パフォーマンス問題
- ✅ **ER-DEVICE**: HW 故障マーカー

### ロギングレベル

| エラー | Level | 例 |
|-------|-------|-----|
| ER-PARSE, ER-MALFORMED | **WARN** | 通信プロトコル違反を警告 |
| ER-PARAM, ER-SIZE | **INFO** | 不正パラメータ（自動補正可） |
| ER-TIMEOUT | **WARN** | タイムオーバー（再試行推奨） |
| ER-DEVICE, ER-BUSY | **ERROR** | デバイス不全（即時対応） |
